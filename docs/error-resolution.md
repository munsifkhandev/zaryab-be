# Backend error-resolution report — 2026-11-09

The task in `../../docs/error.md` authorized runtime verification. Commands used
the existing Windows Node 26.13.0 / npm 11.20.0 installation, matching the developer's
Windows dependency tree. Initial Linux npm 9 could not inspect modern install-script
policy and its sandboxed Windows binary invocation failed with a WSL socket error;
checks were rerun through the Windows runtime with approved execution permissions.

## Confirmed causes and fixes

- The historical 124 missing-Prisma-delegate errors did not reproduce. Prisma 7.10.1
  generation, existing ESM imports and TransactionClient typing compile successfully.
  Added `pretypecheck` generation; existing `prebuild` / `preverify` generation remain.
  No schema edits or additional migrations were necessary.
- Reproduced all 23 lint warnings: two unsafe provider stringifications, nine DTO
  instance spreads and twelve unbound test method references. Provider selectors now
  compare supported string literals directly. Content/address persistence and test
  fixtures map fields explicitly. HTTP test cookie helpers bind real service instances,
  preserving `this`. Lint now uses `--deny-warnings` so CI cannot silently accept warnings.
- Added three unit regressions: provider objects cannot trigger custom coercion,
  article mapping preserves dates/fields while excluding unrelated properties, and
  banner updates preserve zero/false values and nullable/omitted dates.

## Dependency audit

Initial audit: five affected packages, including two high, one moderate and two low
findings. Both chains came through development deployment tooling:

```text
@nestjs/mau@0.2.9 -> inquirer@8.2.6 -> external-editor -> tmp
@nestjs/mau@0.2.9 -> undici@6.20.1
```

These packages are not imported by the commerce HTTP runtime, but deployment tooling
still runs with developer/CI privileges. Fixed with overrides scoped to `@nestjs/mau`:
`inquirer@8.2.7` replaces the legacy editor/tmp chain, and `undici@6.29.1` stays within
the existing major. Lockfile was regenerated by npm, retaining the deployment CLI.
No forced remediation or major application framework/Prisma upgrade was used.

Primary references: [Inquirer 8.2.7 release](https://github.com/SBoudrias/Inquirer.js/releases/tag/inquirer%408.2.7),
[tmp traversal advisory](https://github.com/advisories/GHSA-ph9p-34f9-6g65),
[Undici patched-version advisory](https://github.com/advisories/GHSA-4qv8-2p9j-2685).
The final native npm audit returned exit 0, an empty vulnerability object and zero
findings at every severity, covering development and production dependencies.
`mau --help` also exited 0 after the compatible overrides; no cloud deployment ran.

## Install-script decisions

Inspected installed package identities, manifests and installer entry points, then
recorded a narrow policy in `package.json`:

| Package | Decision | Purpose |
| --- | --- | --- |
| `@prisma/engines@7.10.1` | Allow exact reviewed version | Prisma schema-engine installation |
| `prisma@7.10.1` | Allow exact reviewed version | CLI runtime compatibility preflight |
| `argon2@0.45.2` | Allow exact reviewed version | Native addon/prebuilt initialization |
| `msgpackr-extract` | Deny installer | Optional serialization acceleration/build tooling |
| `@scarf/scarf` | Deny installer | Installation telemetry is unnecessary |

Added `.npmrc` with `strict-allow-scripts=true`, pinned npm 11.20.0 in package metadata
and Docker/CI installation, and added `.nvmrc` for Node 24. Initial dependency update
used scripts disabled; subsequent normal `npm install` passed with the reviewed
policy. Final `npm install-scripts ls` reports no unreviewed scripts. This does not
claim a new clean-container install was executed. Actual Argon2id hash/verify,
wrong-password rejection and msgpackr pack/unpack smoke checks all passed.

## Remaining limits

migrated `_test` database; no populated database was reset, migrated or reseeded.
Docker builds, hosted CI, real email/storage/queue acceptance and actual cloud deploy
were not executed. Node 24 remains the Docker/CI/local version-file target: Prisma's

change requires a fresh audit and explicit installer review. Audit results cover
currently published advisories; they are not proof against unknown vulnerabilities.
